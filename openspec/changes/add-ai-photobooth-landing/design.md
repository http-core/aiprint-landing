## Context

Проект пустой (greenfield): есть только ТЗ (`spec.md`) и рендер будки `media/2026-11-01 20.57.59.jpg` (720×1280, низкое качество, будет заменён). Рендер используется **только в карточке товара**; объектив, прорезь печати и прочая «фактура будки» в сценах рисуются векторно/CSS. Финальных AI-портретов нет — до их появления используются заглушки. Хостинг — собственный сервер заказчика (Node). Заявки — в Telegram. Требования — в `specs/`; мотивация — в `proposal.md`.

Цвета оклейки будки (фиолетовый, лайм, коралл) совпадают с акцентами из ТЗ — это основа палитры, чтобы сайт и реальный продукт выглядели одной системой.

## Goals / Non-Goals

**Goals:**
- Ощущение «дорого»: крупная типографика, много воздуха, точная сетка, медленные уверенные движения, один сильный приём на сцену.
- Весь контент — в типизированных данных; замена фото/стилей/моделей без правки компонентов.
- Прогрессивное улучшение: без JS и при reduced-motion страница полна по содержанию.
- Lighthouse (mobile): Performance ≥ 85, Accessibility ≥ 95, CLS < 0.1.

**Non-Goals:**
- CMS/админка, мультиязычность, аналитика (точки подключения оставляем, но не подключаем).
- Генерация финальных AI-портретов (делает заказчик из выбранного исходного фото).
- Smooth-scroll библиотеки (Lenis и т.п.) — они перехватывают нативный скролл, что противоречит ТЗ.
- WebGL/3D.

## Decisions

### D1. Astro 5 + Node-адаптер (standalone)
Страница — статика (prerender), единственный on-demand маршрут — `src/pages/api/lead.ts` (`prerender = false`). Запуск: `node dist/server/entry.mjs` за nginx.
- *Почему:* минимум JS на клиенте, встроенная оптимизация изображений (`astro:assets` + sharp → AVIF/WebP, `width/height` против CLS), компонентная структура сцен, серверная ручка в том же проекте.
- *Альтернативы:* Next.js — тяжелее рантайм для одностраничника; Vite + отдельный Express — два артефакта деплоя; чистый HTML — нет оптимизации изображений и типизации данных.

### D2. GSAP + ScrollTrigger для скролл-анимаций
`pin` + `scrub` для плёнки и печати, `ScrollTrigger.matchMedia`/`gsap.matchMedia()` для веток desktop / mobile / reduced-motion. Таймлайны — функции от прогресса скролла → детерминированность при прокрутке назад (spec: scroll-story).
- *Почему:* надёжный pin с корректным `pinSpacing`, refresh при ресайзе, `scrub` со сглаживанием; бесплатен для коммерции.
- *Альтернативы:* CSS `animation-timeline: view()` — нет в Firefox, нет pin; Framer Motion — требует React; IntersectionObserver вручную — много кода для pin/scrub.
- Сцена 1 (вспышка) — короткий GSAP-таймлайн, запускаемый один раз (не scrub), флаг в `sessionStorage` (с try/catch) чтобы не повторять.

### D3. Склейки сцен через «общие якорные размеры», а не FLIP между секциями
Перенос DOM-узлов между секциями хрупок при ресайзе. Вместо этого каждая пара соседних сцен договаривается о геометрии через CSS-переменные (`--frame-w`, `--frame-ratio`, позиция центра):
```
Сцена 1 конец:   портрет в центре, размер = --frame-w
Сцена 2 начало:  первый кадр плёнки в центре, тот же размер и то же изображение
Сцена 2 конец:   4 варианта, выбранный отмечен лаймовой рамкой и бейджем
Сцена 3:         именно этот снимок выезжает из прорези и встаёт в рамку на полочке
Сцена 3 конец:   рамка на полочке остаётся в кадре, пока въезжает карточка сцены 4;
                 в карточке рядом с будкой стоит тот же отпечаток
```
Визуально это один объект, технически — разные элементы с одинаковым изображением и совпадающей позицией на стыке.
Склейка 1→2 реализована точно: портрет, оставаясь почти неподвижным, сдвигается так, чтобы в момент закрепления
плёнки совпасть с первым (пустым) кадром; позиции считаются по `offsetTop`-цепочке (без учёта transform).

### D5. Модель данных и заглушки
Zod-схемы валидируют данные при сборке. Каждое неподтверждённое значение обёрнуто в `ph(value)` → `{ value, placeholder: true }`. Главная страница при пререндере собирает их (`lib/placeholders.ts`) и печатает предупреждение в production-сборке — отдельная интеграция не нужна. В dev элементы с заглушками получают `data-placeholder` и обводятся пунктиром. Модель «Будка 1.0» со всеми характеристиками помечена как заглушка, цена отсутствует → «Стоимость по запросу».

### D6. Визуальная система
- Фон `#FAF8F3` (молочный) / `#FFFFFF`; текст `#141414`; акценты: фиолетовый `#6B4EFF`, лайм `#C8F04A`, коралл `#FF6B57` — используются точечно (подсветка шага, выбранный вариант, фокус, CTA-hover).
- Шрифты (self-host через Astro Fonts API, провайдер `local` с файлами из `@fontsource`; кириллица + латиница, `font-display: swap`, метрические фолбэки `size-adjust` генерируются автоматически, preload основного шрифта): **Onest** (заголовки/текст, крупные кегли до `clamp(3rem, 9vw, 9rem)`), **Playfair Display Italic** (акцентные слова в заголовках — «editorial»), **JetBrains Mono** (маркировка плёнки: номера кадров, «AI-66 ▸ 24A»).
- Аналоговая фактура: тонкий SVG-шум поверх фона (opacity ~3%), белые поля отпечатков, тени «бумаги».
- Заглушки портретов: генерируемые при сборке SVG-дуотоны (силуэт + градиент в цветах стиля + название стиля), чтобы макет выглядел цельно, пока нет фото.

### D7. Мобильная ветка
- Плёнка горизонтальная на всех ширинах (на узком экране виден один кадр и края соседних). Pin: desktop ≈ кадры × 40vh + 80vh, но ≤ 300vh; < 768px — ≤ 140vh (меньше половины). Микродвижения кадров только ≥ 768px.
- Печать: ≥ 900px закрепляется вся секция (две колонки, шаги рядом), pin 160vh; < 900px закрепляется только блок с прорезью и рамкой, вместо списка шагов в нём строка «N/4 · текущий шаг», полный список идёт сразу после; pin 80vh.
- Hero: «разнесённый» заголовок вокруг объектива — только ≥ 1100px, ниже — обычный поток.
- `overflow-x: clip` на `body` + контроль ширины в e2e-тестах на 320/375/414.

### D8. Форма и `/api/lead`
- Общий модуль валидации (клиент + сервер). Клиент: машина состояний `idle → submitting → success | error | not_configured | rate_limited`; `AbortController` с таймаутом 15 с.
- Сервер: проверка `Content-Type`, размер тела ≤ 8 КБ, валидация, honeypot, rate-limit 5/10 мин по IP (`X-Forwarded-For` доверяем только при `TRUST_PROXY=1`), `sendMessage` с `parse_mode: HTML` и экранированием. Env: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`.
- Кнопка «Обсудить покупку» в карточке ставит модель в скрытое поле и показывает её в форме чипом «Модель: Будка 1.0 ✕».
- Ссылка «написать в Telegram» (фолбэк при ошибке) — на контакт из `site.ts` (по умолчанию `@AI66Robot`, заменяемо).

### D9. Тестирование
- Vitest: валидация, экранирование, rate-limit, обработчик `/api/lead` с замоканным `fetch`.
- Playwright: отсутствие горизонтального переполнения (320/375/768/1440), reduced-motion — все сцены в финальном состоянии без pin, форма (успех / ошибка / not_configured через мок маршрута), отсутствие ошибок консоли, отсутствие запросов разрешений.
- Ручная проверка: Safari iOS, Chrome Android, Chrome/Firefox/Safari desktop.

## Risks / Trade-offs

- [Рендер будки 720×1280 выглядит мыльно в крупном размере] → используем только в карточке, ограничиваем отображаемый размер ~ натуральным, файл — в конфиге для замены.
- [Заглушки портретов снижают «вау»-эффект] → стильные SVG-дуотоны в единой палитре; ТЗ на финальные фото фиксируем в Open Questions.
- [Pin + iOS Safari: прыжки при скрытии адресной строки] → `ScrollTrigger.config({ ignoreMobileResize: true })`, единицы `svh`/`lvh`, `normalizeScroll` не используем (перехват скролла).
- [In-memory rate-limit сбрасывается при рестарте и не работает в кластере] → приемлемо для одного процесса; при масштабировании — вынести в Redis.
- [GSAP ~70 КБ] → загружаем модулем после первого рендера; сцена 1 без JS показывает портрет статично.
- [Вспышка и фоточувствительность] → одна вспышка ≤ 300 мс, opacity ≤ 0.85, отключена при reduced-motion.

## Migration Plan

Новый проект — миграции нет. Деплой: `npm ci && npm run build` → `node dist/server/entry.mjs` (PORT, HOST) за nginx с HTTPS; `.env.example` с переменными Telegram. Откат — предыдущая сборка.
